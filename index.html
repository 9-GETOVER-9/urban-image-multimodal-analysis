🎯 项目背景：解决什么问题？

在「智慧城市」「数字政府」等 ToB/ToG 项目中，需要对海量城市监控图像进行结构化分析。传统方案 vs 本项目方案：

❌ 传统小模型方案

每个标签类别训练独立模型 → 标签体系扩展时成本剧增 → 标注任务异常艰巨 → 模型泛化能力弱 → 维护 N 个模型的部署和更新

✅ 多模态大模型方案（本项目）

一个 VLM 处理所有标签任务 → 新增标签只需修改 Prompt → 标注成本大幅降低 → 泛化能力强 → 单模型部署维护简单

🧠 核心技术：Prompt 工程设计

采用「单次推理多任务」策略——一个 Prompt 同时完成三类标签识别，降低 API 调用成本，且模型能在任务间建立语义关联：

# prompts.py - 核心 Prompt 模板 def build_analysis_prompt() -> str: device_str = "、".join(DEVICE_TYPES) scene_str = "、".join(SCENE_TAGS) element_str = "、".join(ELEMENT_TAGS) prompt = f"""你是一位城市图像分析专家，擅长对城市监控画面进行结构化分析。 请仔细观察这张图像，并严格按照以下要求完成三项分析任务： **任务1 - 设备类型判断：** 根据画面的拍摄角度、视野范围等信息，判断拍摄该图像的设备属于以下哪一类： {device_str}。只能选择其中一种。 **任务2 - 场景标签识别：** 判断画面中主要展现的场景属于以下哪些类别： {scene_str}。可以选择一个或多个。 **任务3 - 画面要素识别：** 识别画面中是否出现以下要素： {element_str}。可以选择零个、一个或多个。 请严格按照以下JSON格式输出结果： ```json {{ "device_type": "从设备类型中选择一种", "scene_tags": ["从场景标签中选择一个或多个"], "element_tags": ["从画面要素中选择零个、一个或多个"] }}```""" return prompt

🎓 面试要点

高频面试问题与回答口径：

Q1: 为什么选择多模态大模型而不是传统小模型？

传统方案需要为每个标签类别训练独立模型，当标签体系扩展时成本剧增。多模态大模型的优势在于：① 泛化能力强，一个模型处理所有标签任务；② 标注成本低，只需少量样本即可达到较好效果；③ 扩展灵活，新增标签只需修改 Prompt，无需重新训练。

Q2: 如何处理多标签任务中的标签依赖问题？

使用 Seq2Set 策略：在训练数据准备阶段，穷举多标签的所有排列组合。例如 3 个标签生成 6 条训练样本，避免模型学习到错误的标签顺序依赖。

Q3: 这个项目的核心工程难点是什么？

三个核心难点：① Prompt 工程——设计能同时完成多任务的结构化 Prompt；② 结果解析——处理模型输出的非标准 JSON（markdown 包裹、多余文本等）；③ 标签校验——确保输出标签在合法范围内，过滤幻觉标签。

Q4: 为什么用 API 调用而不是本地部署？

项目定位是验证「VLM 替代小模型」的技术路径可行性。API 调用零 GPU 门槛，适合快速验证；同时提供了 LoRA 微调方案作为后续优化路径——验证通过后可微调部署到本地，实现成本可控。
